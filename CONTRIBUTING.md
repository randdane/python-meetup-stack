# Contributing to Python Meetup Stack

Thank you for your interest in contributing! This project is designed to help Python developers embrace containerization through practical, lightweight examples.

## 🤝 How to Contribute

### 🐛 Reporting Issues
- Use the [GitHub Issues](https://github.com/randdane/python-meetup-stack/issues) page
- Provide clear descriptions of the problem
- Include your system information (OS, Docker version)
- Add relevant logs or screenshots

### 💡 Suggesting Improvements
- Open an issue with the "enhancement" label
- Describe your idea and its benefits for the meetup community
- Consider how it aligns with the project's simplicity goals

### 🔧 Code Contributions

#### Adding New Services
1. Keep it lightweight (< 500MB RAM per service)
2. Use clear, memorable ports
3. Update documentation
4. Test thoroughly
5. Submit a pull request

#### Improving Documentation
- Fix typos or unclear explanations
- Add new demo scenarios
- Improve setup instructions
- Translate to other languages

#### Python Examples
- Add new demonstration scripts
- Improve existing examples
- Add comments and explanations
- Ensure compatibility with the container environment

## 📋 Development Guidelines

### 🎯 Project Goals
- **Simplicity**: Easy for beginners to understand
- **Lightweight**: Minimal resource requirements
- **Practical**: Real-world Python use cases
- **Educational**: Clear learning objectives

### 🐳 Docker Best Practices
- Use official images when possible
- Pin specific versions for reproducibility
- Minimize image sizes
- Follow security best practices

### 🐍 Python Standards
- Follow PEP 8 style guidelines
- Add type hints where appropriate
- Include docstrings
- Write clear, commented code

## 🔄 Pull Request Process

1. **Fork** the repository
2. **Create** a feature branch (`git checkout -b feature/amazing-feature`)
3. **Commit** your changes (`git commit -m 'Add amazing feature'`)
4. **Push** to the branch (`git push origin feature/amazing-feature`)
5. **Open** a Pull Request

### PR Requirements
- Clear description of changes
- Tests pass (if applicable)
- Documentation updated
- No breaking changes without discussion
